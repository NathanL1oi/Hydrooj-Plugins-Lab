# hydrooj-contest-flexible-start

为 Hydro 灵活时间比赛增加明确的“开始个人计时”确认页，避免学生误点题目列表后立刻开始个人时间窗口。

## 功能

- 将灵活时间比赛里的“参加”理解为登记，登记本身不写入 `startAt`。
- 已登记但未开始时，点击题目列表会先进入 `/contest/:tid/flexible-start` 确认页。
- 确认页展示本次开始时间、预计个人截止时间和个人时长。
- 比赛详情右侧会显示当前个人计时状态。
- 未开始个人计时前，私有比赛附件下载和“提前结束比赛”入口也会先被拦到确认页，避免隐藏入口误写 `startAt`。
- 开始时只写当前用户当前比赛的 `document.status`，不会扫描整场比赛状态。

## 计时和排名语义

这个插件的“开始个人计时”对齐 Hydro 原本的“第一次进入题目列表时自动写入 `startAt`”，不是对齐“参加比赛”。参加比赛仍然只是登记/报名，登记后不会消耗个人时间。

插件只改变 `startAt` 的写入入口，不改变提交、评测和榜单统计逻辑。对于 OI/IOI/Ledo 这类主要按分数排序的赛制，排名语义基本不会因为插件变化而变化。

需要注意的是，Hydro 核心的 XCPC/ACM 规则当前在统计罚时时使用全局 `beginAt` 计算提交时间。如果你希望灵活时间 XCPC 完全按个人 `startAt` 计算罚时和排名，需要额外改比赛规则/榜单统计逻辑；这不是本插件默认处理的范围。

## 为什么第一版不做取消登记

登记不消耗个人计时，真正有后果的是“开始个人计时”。取消登记需要同步维护比赛参加人数、订阅状态、邀请码报名语义和管理员批量添加结果，数据一致性成本比收益更高。

如果后续确实需要，可以只允许 `attend=1` 且 `startAt` 不存在的状态取消，并且必须同步把比赛文档的参加人数减一。

## 安装

```bash
hydrooj addon add C:\Users\zacktan\dev\contest-flexible-start
```

## 数据库负担

插件复用 Hydro 的 `document.status` 索引：

```text
domainId + docType + docId + uid
```

详情页使用已有的 `tdoc/tsdoc`，开始页只读当前用户状态，确认开始只做一次条件点写。插件不调用 `getMultiStatus({ docId: tid })`，也不触发 `recalcStatus()`。
